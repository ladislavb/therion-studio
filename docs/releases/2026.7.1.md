# Therion Studio 2026.7.1

Therion Studio 2026.7.1 focuses on release-stabilization after 2026.6.9, faster repeated project validation, better project outputs handling, a first SQL reporting workflow, and several usability fixes based on tester feedback.

## New Features

- Added a project Outputs sidebar that groups generated Therion exports by type:
  - model outputs: `.lox`
  - map/atlas outputs: `.pdf`
  - database outputs: `.sql`
- Added a read-only SQL report viewer for Therion `export database` files. The viewer imports database exports into an in-memory SQLite database, provides guarded `SELECT` query execution, includes built-in report presets, and exports the current result table as CSV.
- Added compiler output source links: Therion references such as `file.th2 [64]`, `file.th [64]`, and `thconfig [64]` can be clicked to open the source at the reported line.
- Added Markdown export for Validation results.

## Improvements

- Project validation is faster and calmer on repeated runs: unchanged source snapshots, projections, project indexes, and per-file findings are reused, unchanged result trees are not rebuilt, and superseded scans are cancelled earlier.
- Project scanning is more consistent because Validation, Structure, and Outputs now share the same file discovery rules.
- Map editor updates are lighter for simple geometry edits, with narrower source changes, partial scene refreshes, and reduced undo-surface refresh work.
- The Selection inspector is clearer when a new map object will create the first draft scrap.
- New raster background insertion preserves XTherion-compatible metadata while showing the expected model-space position in the inspector.
- Troubleshooting logs now include startup timing checkpoints, and logging enabled from Preferences follows the intended 24-hour expiry.
- Outputs now stay compact by showing filenames for unique artifacts and adding relative-folder context only for duplicate filenames.
- Validation now accepts valid `export map -layout-*` overrides backed by known layout options, treats `code ... endcode` layout blocks as raw backend code, and offers safe fixes for Windows-style backslash path separators while still resolving those paths correctly.
- Project-level validation findings now appear first under `Project` and no longer try to open the project folder as an unsupported file when selected.
- Compiler output is easier to scan because Therion errors are highlighted in red and warnings in orange while keeping source links clickable.
- Project structure, validation, and project-level compilation now infer the default root config from common project config names in priority order: `thconfig`, `thconfig.thconfig`, `main.thconfig`, `index.thconfig`, then `<project_name>.thconfig`.

## Bug Fixes

- Fixed several map-editor interaction edge cases, including false move transactions without a real drag, touch pass-through, point-drag refresh stability, and stale vertex indexes after partial refresh.
- Fixed compiler status reporting so Therion output-write warnings are treated as failed runs even when the process exits with code 0.
- Fixed raster background placement for newly inserted backgrounds in new `.th2` documents.
- Fixed Linux and Windows strict-warning builds after release stabilization changes.
- Unsupported `.3d` model artifacts are no longer shown in Outputs until native support is available.

## Internal Architecture

- Continued the unified source DOM migration by moving more Raw, Blocks, Map, and Validation consumers onto shared logical-command projections.
- Added project source projection caching for validation and project-index workflows.
- Extracted a shared project scan cache service at the main-window composition boundary.
- Moved more map editor area-reference, line-feature, selection-restore, and object-details flows away from local text reparsing.
- Added focused regression coverage for map partial refresh, logical source context wiring, validation cache reuse, and compiler output link parsing.
